# MIMIC-IV-ECG 预训练报告（run `m5fasts1k1`）

## 1. 运行设置

| 项 | 值 |
|---|---|
| 数据 | MIMIC-IV-ECG，manifest 800,035 条；train 720,031 / val 80,004（按行随机划分，seed 42） |
| 模型 | 作者原版 LVCG（GRU 路径），8,285,060 参数 |
| 优化 | AdamW，lr 5e-4 全程固定，weight_decay 0.01，grad_clip 1.0，batch 64 |
| 步数 | 500,000 步（约 44 个 epoch） |
| 硬件 | 单张 RTX 5090，18–20 it/s，约 8 小时 |
| 加速开关 | `vectorized_stitcher=true`、`fast_upsample=true`（与原版数值等价，float64 下误差 < 1e-14） |
| 验证 | 每 1000 步，固定前 50 个 batch（3200 条），遮挡导联的随机种子固定 |

Loss 为作者原版的四项：`recon`（遮挡导联 ECG 重建）、`beat`（VCG 心拍重建）、
`temporal`（状态差的 Huber）、`base`（锚点心拍重建），权重 1 / 1.0 / 0.1 / 1.0。

## 3. 各项的实际含义

`beat` 和 `temporal` 在元素维度上是求和而非取平均（与论文式 (7) 一致），所以数值天然偏大：

| 项 | 末值 | 换算后 | 含义 |
|---|---:|---:|---|
| `beat` | 93.69 | ÷ (3×128) = **0.244** | VCG 心拍的每元素 MSE；信号已 z-score，相当于解释约 76% 方差 |
| `temporal` | 5.21 | ÷ 256 = **0.0204** | 状态差的每元素 Huber |
| `recon` | 0.675 | 本身即每元素 MSE | 3 个可见导联重建 9 个遮挡导联，解释约 32% 方差 |
| `base` | 0.0267 | 本身即每元素 MSE | 锚点心拍（GRU 起点）重建 |

总 loss 94.9 中，`beat` 占 93.7，其余三项合计约 1.2。**梯度基本由 `beat` 主导**
（每元素被放大 384 倍），即模型主要在优化心拍级 VCG 重建。

## 4. 训练分成三个阶段

1. **0 – 100k 步**：所有项同时快速下降，总 loss 136 → 99，`recon` 0.751 → 0.677。
2. **100k – 230k 步**：`recon` 停在 0.675 附近不再改善，`beat` 96.4 → 94.0 缓慢下降。
3. **230k – 500k 步**：`beat` 在 93.5–94.9 之间波动（463k 步的 94.9 是验证集噪声，
   每次只用 3200 条样本），已经收敛；只有 `temporal`（12.6 → 5.2，降 59%）和
   `base`（0.032 → 0.027）还在改善。

换言之，**后半程 27 万步只让时序一致性变好，重建质量没有变化**。若只关心重建，
`step_250000.pt` 与 `final.pt` 几乎等价；`final.pt` 的优势在 GRU 状态预测。

## 5. 与论文的差异（影响结果解读）

- **论文未给出预训练 loss 曲线或收敛步数**，因此上面的数值无法与论文直接对比，
  只能通过 PTB-XL probing 的 AUC 间接验证。
- **`recon` 被代码额外归一化**：论文式 (7) 的 `L_ECG` 是平方范数求和，代码除以了
  （导联数 × 时间长度），相对 `beat` 缩小约 9000 倍。这是作者发布代码的既有行为，
  为与论文结果可比而保持原样。
- **`base` 项不在论文中**：式 (7) 只有三项，`base` 是代码额外添加的。
- **验证集按记录随机划分，非按病人划分**，同一病人可能同时出现在 train 和 val，
  验证 loss 会略偏乐观。对自监督重建任务影响有限。
- **学习率全程固定**：config 里的 `warmup_steps: 2000` 原版训练脚本从未实现，
  也无衰减，这解释了后期的小幅波动。

## 6. 结论与下一步

训练健康且已收敛，`final.pt` 可用于下游评估。下一步：

1. 检查 checkpoint 能被 `LVCGEncoder` 严格加载，且嵌入有限、方差非零。
2. PTB-XL 四个任务的线性探针（10% 标签，seed 42，冻结主干）。
3. 以随机初始化权重跑同一任务作对照，差值即预训练收益。
